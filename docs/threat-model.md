# TamperGuard 威胁模型

> 适用版本：P0 设计。本文描述系统能防什么、不能防什么、只能事后检测什么。所有“能防”都限定在策略列出的受保护路径与已部署的执行层之上；离开这个前提，结论不成立。

## 1. 范围与前提

### 1.1 部署前提

| 前提 | 说明 |
|---|---|
| 保护端在宿主机 root 运行 | `tg-agent` 以 systemd 管理，宿主机运行，不能容器化 |
| 控制面单实例 | `tg-server` 集中部署，SQLite 存储，管理员通过浏览器访问 |
| 发布端默认分机 | 生产环境 `tg-publish` 与被保护节点分开；P0 演示可同机 |
| 保护范围由策略决定 | 只有策略列出的路径受保护，未列出路径不拦截 |
| 执行层 | P0 是 eBPF LSM（代码已落地，待内核验证）；未加载成功时回退 observe（不阻断，真实写入不自动记录）并标记 degraded。fanotify 降级是 P2，未实现。WSL2 内核已启用 bpf LSM，真实阻断效果待验证 |

### 1.2 安全声明

TamperGuard 的定位是“降低未授权写入受保护路径的成功率，并为写入行为留下可校验记录”，不是“主机全面防护”。以下结论必须原样出现在对外材料中：

- 不防 root。攻击者拿到 root 后可以杀进程、卸载或绕过执行层、修改策略与密钥、删除审计。
- P0 若 eBPF 执行器未加载成功，节点会回退 observe：不阻断，真实写入也不会自动产生审计记录。这时不能认为目录受保护，管理端必须把它标为降级。
- 当前版本没有应用层 RASP。不防内存中的 webshell、不防应用层逻辑漏洞利用。
- 不做恶意内容检测。合法发布通道写入的内容是否安全，不在本产品判定范围内。
- 不做文件回滚与内容恢复。写入成功或攻击成功后，产品不会自动还原。
- 不做网络侧防护。不阻断回连、横向移动、数据外传。

### 1.3 基线可信性

首次把目录纳入保护时，目录里已有的内容会被当作正常内容保留，因为本产品不做内容完整性基线校验。因此：

- 首次启用保护必须在维护窗口内完成，先确认目录干净，再让策略生效。
- 如果先被污染再建立保护，污染内容不会被发现，等于“先污染再建基线”。
- 需要“发现已有 webshell”时，应配合外部文件完整性工具或人工排查；本产品不提供这项能力。

## 2. 资产清单

| 编号 | 资产 | 被破坏后的影响 | 现有控制 |
|---|---|---|---|
| A1 | 受保护目录内容与发布产物 | 网页被植入后门、内容被篡改、业务被替换 | eBPF LSM 阻断（代码已落地，待内核验证）；observe 回退不阻断、真实写入不自动记录；策略/攻击判定事件进审计 |
| A2 | 发布令牌 | 在有效期内冒用发布授权 | 短 TTL（≤15 分钟）、绑定节点/路径/manifest、可吊销、发布端内存持有不落盘 |
| A3 | 发布端 mTLS 身份私钥 | 冒充发布端申请令牌、提交 manifest | 本机 0600、mTLS、可撤销节点 |
| A4 | Agent 身份私钥 | 冒充节点上传审计、伪造审计记录 | 本机 0600、mTLS、可撤销节点 |
| A5 | 策略快照与策略签名私钥 | 下发任意策略，等于取消防护 | Ed25519 签名、Agent 验签 |
| A6 | 令牌签发私钥 | 伪造任意发布令牌 | 服务端 0600；泄露即整体失效 |
| A7 | CA 私钥 | 签发任意 Agent/发布端证书 | 服务端 0600；泄露即整体失效 |
| A8 | 管理端口令与会话 | 改策略、审批降级、走发布流程 | 口令哈希、HttpOnly 会话、HTTPS |
| A9 | 审计链与审计日志 | 无法追溯谁改了什么 | seq + prev hash + Ed25519 签名 + 服务端验链 |
| A10 | 服务端 SQLite 数据库 | 丢失节点、策略、审计、撤销状态 | 文件权限；无加密、无外部不可变副本 |
| A11 | bootstrap token | 注册一个冒充的 Agent/发布端 | 一次性使用、带外交付；TTL 待确认 |
| A12 | 执行层进程与程序完整性 | 防护失效或降级 | 心跳、degraded 标记、管理端告警 |
| A13 | 发布内容本身 | 恶意内容被“合法”发布上线 | manifest 摘要绑定与审计；内容安全不判定 |
| A14 | 主机内核与系统完整性 | 一切上层控制都可被绕过 | 超出产品能力 |

## 3. 信任边界与攻击面

### 3.1 信任边界

| 边界 | 跨越方 | 保护手段 | 主要风险 |
|---|---|---|---|
| 浏览器 ↔ tg-server | 管理员 | HTTPS、会话 Cookie | 账号被盗、钓鱼、管理端 XSS/CSRF |
| tg-server ↔ tg-agent | 节点 | mTLS + CA + 证书 CN 映射 | 证书/私钥失守后可冒充节点 |
| tg-server ↔ tg-publish | 发布端 | mTLS + 服务端签发令牌 | 发布端被控后成为合法写入者 |
| tg-agent ↔ Linux 内核 | 执行层 | root 权限、eBPF LSM（fanotify 为 P2） | root 可篡改、可 detach、可卸载 |
| tg-publish ↔ 受保护节点 | 发布内容 | 令牌 + manifest + 目标节点 grant | 内容传输通道本身不在保护范围 |
| 管理员 ↔ 策略/审批 | 人 | 会话认证 | 内鬼与误操作无法靠技术手段区分 |
| 构建/分发链路 | 构建者 | 无签名、无 SBOM | 供应链投毒 |

### 3.2 攻击面

| 攻击面 | 暴露情况 | 备注 |
|---|---|---|
| Web 业务应用 | 对公网开放 | 本产品不修应用漏洞，只保护目录 |
| 管理端 HTTP 接口 | 管理网/内网 | 登录、策略、发布、审批、审计查询 |
| mTLS 接口 | 节点可访问 | enroll 用 bootstrap token，其余要客户端证书 |
| 受保护路径的本机写入 | 本机任意进程 | 主要拦截面 |
| 执行层进程本身 | 本机 root | root 可直接杀 |
| 发布端与目标节点之间的内容传输 | 部署决定 | 传输通道可能不加密、不校验，需单独评估 |
| 构建产物与依赖 | 开发者/CI | 当前无二进制签名与依赖审计 |

## 4. 对手模型与能力判定

### 4.1 对手清单

| 对手 | 能力假设 | 主要目标 |
|---|---|---|
| 远程未授权攻击者 | 能访问 Web 应用，无任何系统凭据；可能利用应用漏洞获得 Web 用户权限 | 植入 webshell、篡改页面、留后门 |
| webshell 持有者 | 已在 Web 用户权限下执行命令，但未提权 | 持久化、改文件、横向 |
| 内鬼 | 持有管理员账号、发布端身份或运维权限之一 | 静默改内容、绕过流程、掩盖痕迹 |
| 已获取 root 的攻击者 | 完全控制主机 | 关防护、改内容、清痕迹 |
| 供应链攻击者 | 能影响依赖、构建、发布源或密钥的分发 | 在合法产物中植入后门、伪造身份 |

### 4.2 远程未授权攻击者

| 能防 | 不能防 | 只能检测 |
|---|---|---|
| 通过应用漏洞把 webshell 写入受保护路径（open/create 阶段被拒） | 应用层漏洞本身，以及漏洞利用后在内存中执行的代码 | 被拒绝的写入尝试（路径、频率、来源进程） |
| 直接覆盖、删除、重命名受保护目录中的已有文件 | 读取源码、配置文件、数据库内容 | 对受保护路径的探测式访问与多次失败 |
| 通过管理端或 mTLS 接口无凭据调用受保护操作 | 写未受保护路径（上传目录、缓存目录、`/tmp`）后从那里执行 | 管理端登录失败与异常来源（取决于服务端日志实现） |
| 用伪造/过期令牌写入 | 拿到 Web 用户权限后的网络回连、横向移动 | 无法检测内存型 webshell 的存在 |

边界说明：防护只对“写入受保护路径”生效，且要求执行层真正加载成功。如果节点回退 observe，上述写入不会拒绝，可能只有记录、甚至没有记录。攻击者拿到 Web 用户权限后仍可读代码、连数据库、发起网络请求；如果上传目录不在保护路径内，webshell 可以先落到上传目录，再从那里执行。策略必须按实际业务覆盖上传、缓存、模板等目录，未覆盖的部分不享受任何保护。

### 4.3 webshell 持有者

| 能防 | 不能防 | 只能检测 |
|---|---|---|
| 用 webshell 新增、修改、删除受保护文件（eBPF hook 覆盖 open/write/create/unlink/rename/setattr/mmap；observe 回退不阻断） | webshell 已在内存中执行，读取源码与配置 | 被阻断的写入尝试与尝试路径 |
| webshell 借合法发布身份以外的路径写入受保护目录 | 写未保护路径，借未保护路径落地工具或二次载荷 | 保护启用前就已存在的 webshell（无基线校验，发现不了） |
| 借已打开 fd 持续写（eBPF 的 `file_permission` 覆盖；observe 回退不覆盖） | 提权到 root 后的全部行为（见 4.5） | 通过授权发布通道写入的恶意内容（有审计，需人工判断） |
| 用发布令牌直接写入（没有发布端身份与 grant 时不行） | 内存马、无文件攻击、进程注入 | 被拒绝后转向其他路径的行为模式 |

实际风险：webshell 最常见的持久化方式是写文件。文件写入被阻断后，攻击者仍可能通过内存马、计划任务、未保护目录、数据库写马等方式维持访问，这些都需要其他安全产品配合。

### 4.4 内鬼

内鬼按权限细分，结论不同：

| 类型 | 能防 | 不能防 | 只能检测 |
|---|---|---|---|
| 普通运维（无策略修改权、无发布端身份） | 绕过发布流程直接改受保护文件 | 用主机上已登记的例外进程写文件（如果被加入策略） | 所有写入与拒绝记录 |
| 发布端身份持有者 | 用该身份发布任意内容；但发布路径受令牌范围与 TTL 限制 | 内容是否恶意；发布端主机被其控制后自行计算 manifest | 发布申请、令牌签发、写入记录；需人工审核内容 |
| 管理员账号持有者 | 基本不能防：可改策略、加白名单、走发布流程、审批降级 | 删除服务端审计数据、改策略、造发布请求 | 审计记录仍在，但“有权限的人做合法动作”与攻击难以自动区分 |

内鬼场景的核心缺口是“授权本身合法”。产品能提供的是身份绑定的操作记录与范围限制，不能判断操作动机。需要双人审批、账号分权、发布内容人工审核的组织流程配合，这些当前都未实现。

### 4.5 已获取 root 的攻击者

| 能防 | 不能防 | 只能检测 |
|---|---|---|
| 基本不能防。可能在攻击者尚未察觉防护存在时挡住个别写入，不能作为承诺 | 杀 `tg-agent`（link 随进程关闭而 detach）、卸载或 detach BPF 程序、改内核启动参数去掉 bpf LSM | 心跳中断、节点离线 |
|  | 以 `lsm=` 参数重启去掉 bpf、换内核、卸载模块 | 审计 seq 缺口、seq 回退、链分叉告警 |
|  | 读 Agent/发布端私钥、伪造审计记录、替换 Agent 二进制 | 降级标记、enforcer 异常记录（若 Agent 还在运行） |
|  | 直接改策略文件、改服务端数据库、删除本地审计 | 离线后仍可检测到“节点消失”，但无法还原内容 |
|  | 挂载覆盖受保护路径、直接写块设备、ptrace 进程 | 无可靠检测 |

结论：root 级对抗只能依靠审计告警、主机隔离与事后取证，且这些手段在 root 主动对抗时也可能失效。任何“全面防护”“防篡改不可绕过”的表述都不成立。

### 4.6 供应链攻击者

| 能防 | 不能防 | 只能检测 |
|---|---|---|
| 在 manifest 批准之后替换发布内容（发布端复核 + 令牌摘要绑定，正常二进制下） | 在 manifest 生成之前污染发布源（发布端自己算的摘要会认可恶意内容） | 发布内容与审计记录（需人工比对） |
| 伪造/篡改令牌（没有令牌签名私钥时） | 在 Go 依赖、构建脚本、CI 中植入后门，产物仍被正常部署 | 产物哈希、依赖清单、SBOM（当前均未实现） |
| 无 CA 私钥时伪造节点/发布端身份 | CA 私钥、令牌签名私钥、策略签名私钥失守后的身份伪造 | 密钥泄露后的异常注册、异常签发（依赖日志与人工巡检） |
| 无 bootstrap token 时注册新节点 | 自动更新通道被劫持后下发恶意二进制 | 二进制签名校验（未实现） |

## 5. 发布通道滥用

### 5.1 场景矩阵

| 场景 | 攻击者能力 | 结果 | 现有控制 |
|---|---|---|---|
| 令牌泄露（内存、进程转储、发布端主机被控） | 能读发布端内存/进程或控制发布端主机 | 只泄露令牌本身无法凭空制造写入：令牌有 TTL、节点、路径与 manifest 限制，且目标节点 grant 由服务端下发 | TTL ≤15 分钟、吊销、路径范围、令牌不落盘 |
| 发布端主机被完全控制 | 持有发布端身份私钥，可执行任意程序 | 可提交恶意 manifest 并写入令牌范围允许的路径 | 发布申请归属、路径范围、审计；无法阻止 |
| manifest 提交后内容被替换 | 能改发布暂存内容 | 正常发布端写前复核会发现摘要不一致并中止 | manifest 摘要绑定 |
| 发布端二进制被替换后复核失效 | 发布端主机 root | 路径范围内的任意内容都可以写入，审计仍显示合法发布 | 审计记录可追溯，但无法阻止 |
| 令牌重放到另一节点 | 持有令牌 | 被拒绝：令牌绑节点，grant 也只下发到目标节点 | 节点绑定 |
| 令牌过期后使用 | 持有过期令牌 | 被拒绝：TTL 与 grant 到期时间双重检查 | 双端时间检查 |
| 令牌有效期内同 uid 冒用 | 能在目标节点以发布端相同 uid 执行进程（演示默认 uid 0 即 root） | 内核按 uid 放行，令牌窗口内同 uid 的任何进程都能写被授权路径 | 生产用专用非 root uid、缩短 TTL、发布完成后立刻吊销 |
| 撤销生效前抢写 | 持有即将被吊销的令牌 | 最坏约一个心跳周期（默认 15 秒，满足 30 秒上限）内可能完成一次写入 | 心跳下发撤销列表，无法完全消除窗口 |
| 用发布身份写未授权的业务内容 | 合法发布端身份 | 如果策略与发布范围允许，写成功；产品不判断内容安全 | 审计 + 人工审核（当前无强制审核流） |

### 5.2 manifest 绑定的作用与局限

作用：

- 令牌只对一次发布有效，绑定发布端、目标节点、路径范围与 manifest 摘要；令牌被盗后不能任意改写成其他内容。
- 批准之后、落盘之前的内容替换会被发布端的写前复核发现。
- 服务端与审计链只接收摘要与结果，不接触明文内容，减少内容泄露面。
- 哪次发布写了哪些文件，可以按 token_id 与 manifest 回溯。

局限：

- manifest 由发布端自己计算。发布端被控制时，恶意内容会成为“被批准的摘要”，内容哈希绑定不起作用。
- 内核与执行层只按 uid 与 inode/路径授权，不校验文件内容。绕过发布端复核（替换二进制、伪造写入路径）时，执行层不会发现内容与摘要不一致。
- 发布完成后没有对线上内容做回查，不保证文件仍然等于 manifest 描述的内容。
- manifest 摘要已实现：按相对路径排序后对 `路径\tSHA-256\n` 求 SHA-256；文件大小不参与摘要；符号链接与非普通文件被拒绝。权限位、空目录、文件名编码等边界尚未纳入摘要；摘要算法变更需要版本化。
- 内核授权粒度是 uid，不是进程：令牌窗口内同一 uid 的所有进程都能写被授权路径，默认演示 uid 0 时等于 root 在窗口内可写。发布端必须使用专用 uid。
- 当前 eBPF 实现存在原语缺口：`mmap_file`/`file_mprotect` 不查父目录保护集，`inode_link` 不查源 inode，非递归单文件规则的 `unlink`/`rename` 依赖父目录；`process` 写入者规则尚未进入内核判定。这些在补齐前不能算“已覆盖”。
- `observe` 规则在 eBPF 节点上不生效；新建子目录要等索引重建才进入保护集，刷新窗口内可能漏拦。

### 5.3 吊销窗口

- 服务端写入撤销记录后，通过心跳响应下发撤销列表，默认 15 秒一个周期，最坏约一个周期；SSE 推送是 P1 设计项，当前未实现。
- 撤销到达前已经开始的写入不会被中断；已经完成的发布不会回滚。
- 如果节点离线，撤销无法到达，只能等节点恢复心跳；离线期间的写入不受保护。

## 6. 管理端被攻破

### 6.1 影响面

| 能力 | 后果 |
|---|---|
| 修改策略 | 把攻击者进程加入白名单、移除保护路径、把 enforce 改 observe，防护被静默削弱 |
| 审批降级 | 把降级节点标为已审批，弱防护被当作可用状态 |
| 注册节点/发布端 | 用 bootstrap token 引入冒充身份，写入受保护路径 |
| 创建发布申请 | 让合法发布端写任意内容，或把发布指向敏感路径 |
| 查看审计 | 获取主机路径、发布历史、运维信息 |
| 吊销/删除节点 | 制造防护盲区或拒绝服务 |
| 删除服务端审计记录 | 丢失追溯依据（无法修复） |

### 6.2 仍然有效的控制

- 已写入本地的审计记录由 Agent 私钥签名，服务端无法在没有 Agent 私钥的情况下伪造其他节点的历史记录。
- 其他节点的心跳与审计链继续独立工作；单点管理端失守不直接等于所有节点失守。
- 节点侧的策略快照有签名，未签名的策略不会被加载；但攻击者若同时拿到策略签名私钥，此控制失效。

### 6.3 缺口

- 管理端账号没有强制双因素认证，没有双人审批。
- 管理员操作的服务端审计是否完整记录，当前未确认。
- 服务端数据库没有加密，也没有外部不可变副本；服务端被控后，审计删除无法被本系统发现。
- 没有“关键操作二次确认”机制。

## 7. 降级攻击

攻击者主动让主执行层不可用，迫使系统进入弱防护或失去防护。

### 7.1 攻击方式

| 方式 | 所需权限 | 结果 | 检测 |
|---|---|---|---|
| 以不带 `bpf` 的 `lsm=` 参数重启 | root | eBPF LSM 不加载 | 节点重启后心跳显示降级；重启期间离线 |
| 换用不支持 BPF LSM 的内核 | root | 执行器加载失败，回退 observe（不阻断） | 降级标记与心跳字段 |
| 杀掉 `tg-agent` | root | 停止心跳；LSM link 未 pin，进程退出后 link 关闭、受保护路径恢复放行，直到 Agent 重启 | 3 个心跳周期（45 秒）后离线告警 |
| detach BPF 程序 / 移除 hook | root | 写入不再被拦 | Agent 自检可能发现；root 可同时禁用 Agent，无法可靠检测 |
| 队列/资源耗尽导致监听进程异常 | root 或资源竞争 | fanotify 事件丢失或阻塞（P2；P0 没有 fanotify） | 溢出计数、进程重启记录、心跳异常（P2） |
| 制造 BPF 加载失败的条件（替换 BTF、限制特权） | root | 启动即降级 | 降级原因进入心跳与审计 |

非 root 用户通常无法让 eBPF 或 fanotify 失效；但可能通过资源竞争影响 Agent 稳定性，需要按实际环境评估。

### 7.2 检测与响应

- 心跳中的 `enforcer`、`degraded`、`caps`、`enforcer_healthy` 字段是主要信号；服务端据此标红。
- 降级节点未审批时不计合规；审批只是接受弱防护，不等于恢复。
- 管理端应对“运行中突然降级”与“启动即降级”区分展示；二者可疑程度不同，具体 UI 行为待实现。
- 离线超过 3 个心跳周期（45 秒）标记 offline。

### 7.3 现状

- P0 主执行层是 eBPF LSM（代码已落地，待内核验证）。执行器未加载成功时回退 observe，observe 不阻断、真实写入也不自动记录，等价于没有文件写入阻断能力。
- fanotify 是 P2 的弱防护，尚未实现；落地后也只是 open 阶段拦截，不覆盖已打开 fd、rename、unlink、mmap。
- 降级攻击不可能被完全防住，因为执行层运行在攻击者最终控制的同一台主机上。

## 8. 审计日志被删除或修改

### 8.1 记录位置与状态

| 位置 | 内容 | 谁能改 | 检测手段 |
|---|---|---|---|
| Agent 本地 JSON Lines | 完整链，含尚未上传记录 | root、Agent 用户 | 链自校验、服务端缺口检测 |
| 服务端 SQLite | 已上传记录、每 Agent 的 next_seq/last_hash | 服务端管理员、root | `/audit/verify` 重新验链；数据库被删无外部比对 |
| 管理端展示 | 审计查询结果 | 服务端 | 只读视图，不作为证据源 |

### 8.2 对抗矩阵

| 攻击动作 | 机制 | 可检测性 |
|---|---|---|
| 修改一条记录的内容 | hash 变化、签名失效 | 可检测（服务端验链告警） |
| 删除中间记录 | seq 跳号、prev hash 不匹配 | 可检测 |
| 删除末尾尚未上传的记录 | 已上传部分仍自洽 | 下次上传 seq 跳号时告警；心跳 `audit_seq` 对账是设计项，当前未实现；从未上传的记录不可恢复 |
| 清空本地日志并让 Agent 从 seq=1 重启 | 服务端期望的 next_seq 远大于 1 | 可检测（缺口/回退告警） |
| 用窃取的 Agent 私钥签名伪造记录 | 签名与链均自洽 | 不可区分，属于 root/密钥失守 |
| 删除服务端数据库中的记录 | 服务端只做“收到的记录之间”校验 | 本系统内不可检测；只能靠外部备份/导出比对 |
| 重放旧记录 | seq 已被消费，prev 不匹配 | 可检测 |
| 修改记录时间戳后重新签名 | 有私钥即可 | 不可检测（`ts` 没有独立时间戳背书） |

### 8.3 关键结论

- 链式哈希只能发现修改，不能发现删除；防删除依赖 seq 单调递增与服务端缺口检测，两者必须同时存在。
- 服务端状态是“删除检测”的参照物。服务端被攻破或数据库被清空时，删除检测失效。
- 本地尚未上传的尾部记录被删除，在服务端没有见过的情况下无法恢复。
- 建议部署时把审计记录实时导出到独立日志平台（未实现，需要另行建设）。

## 9. 剩余风险清单

| 编号 | 风险 | 影响 | 当前状态 |
|---|---|---|---|
| R1 | root 攻击者可关闭防护、伪造审计 | 防护与追溯都失效 | 明确不防；靠隔离与外部日志缓解 |
| R2 | 部署前已存在的 webshell/污染内容 | 不会被发现，继续可用 | 无基线校验；需维护窗口与外部排查 |
| R3 | P0 eBPF 执行器未在目标内核验证；失败回退 observe | 可能不阻断且不自动记录真实写入，节点被误认为已防护 | 代码已落地，内核验证待做；以 `enforcer` / `degraded` 字段标红 |
| R4 | eBPF hook 覆盖不完整（mmap 父目录、link 源 inode、单文件规则 unlink/rename、process 规则未接线、observe 接线、索引刷新） | 存在未被覆盖的写入原语与漏拦窗口 | 代码已落地，缺口待补；未验证前不作为承诺 |
| R5 | 网络文件系统（NFS/CIFS）行为不保证 | 阻断可能失效或误伤 | 不承诺；需按环境验证 |
| R6 | 容器/OverlayFS 场景未验证 | 路径与 inode 不匹配，可能漏拦 | P3 验证，不在 P0 承诺 |
| R7 | 发布端被完全控制 | 可发布恶意内容，摘要绑定失效 | 无法阻止；审计 + 人工审核 |
| R8 | 管理端被攻破或管理员账号被盗 | 策略、发布、审批全部可被操控 | 单点信任，无双人审批/2FA |
| R9 | CA 与签名私钥无 HSM/TPM、无轮换 | 密钥泄露即整体失效 | 未实现密钥保护 |
| R10 | Agent 私钥可被 root 读取 | 审计伪造、身份冒充 | 无 TPM 绑定 |
| R11 | 服务端审计无外部不可变副本 | 服务端删除不可检测 | 未实现导出/备份 |
| R12 | 策略误配导致业务写入被拒 | 可用性事故 | 有 observe 设计但不适用于 eBPF 节点；无自动回滚 |
| R13 | 时钟不同步或回拨 | 令牌窗口、审计时间不可靠 | 依赖时钟同步，未做独立时间戳 |
| R14 | 构建产物未签名、依赖未审计 | 供应链投毒不可发现 | 未实现 SBOM/签名 |
| R15 | 发布端与节点跨机部署未实现 | 分机场景没有端到端流程 | P0 只支持同机；传输通道需部署侧补 |
| R16 | SQLite 单实例、无高可用 | 控制面故障导致无法发布与告警 | 单机设计，规模上限未测试 |
| R17 | 未做线上内容回查 | 发布后内容被替换不会被发现 | 无完整性扫描 |
| R18 | 授权路径内的合法写入不判断内容 | 内部人员可借合法通道写恶意内容 | 审计可追溯；内容审核不在产品内 |
| R19 | Agent 崩溃或被杀后 LSM link 关闭 | 阻断消失，最长 45 秒后才被服务端判离线 | 已知；pinned link/看护进程待评估 |
| R20 | 内核授权粒度是 uid | 令牌窗口内同 uid 进程都能写；默认 uid 0 等于 root 可写 | 生产必须配置专用 uid；文档与部署检查项 |

## 10. 明确不做

以下事项不在 TamperGuard 的承诺范围内，对外材料与投标响应不得写成“支持”：

| 不做的事 | 说明 |
|---|---|
| 不防 root、不防内核级/固件级/物理接触攻击 | root 可关闭一切防护；不做 Measured Boot、TPM 证明 |
| 不做应用层 RASP | 当前版本没有；Phase 4 规划，未实现 |
| 不做恶意内容检测、病毒查杀、webshell 特征扫描 | 只做授权与审计，不做内容判定 |
| 不做 WAF、IPS、EDR、网络流量防护 | 不替代任何网络侧产品 |
| 不做数据防泄漏（DLP） | 不阻止读取、外传、截图、导出 |
| 不保证 NFS/CIFS 等网络文件系统上的阻断效果 | 支持有限，需单独验证 |
| 不承诺容器场景 | OverlayFS copy-up 与命名空间问题未解决，P3 验证 |
| 不做文件回滚、内容恢复、备份 | 写入拦截失败后不还原 |
| 不做未保护路径的保护 | 策略外路径不拦、不告警 |
| 不承诺发现部署前已存在的后门 | 无基线校验 |
| 不替代等保/合规测评 | 不承诺满足任何具体条款 |
| 不承诺零误报、零漏报 | 执行层能力与策略配置决定效果 |
| 不承诺密钥不泄露 | 无 HSM/TPM，密钥以文件形式存放 |
| 不承诺审计不可删除 | 服务端数据库可被有权者删除，需外部日志配合 |

## 附录 A STRIDE 对照

| STRIDE | 对本系统的含义 | 现有控制 | 主要缺口 |
|---|---|---|---|
| Spoofing（身份伪造） | 冒充 Agent、发布端、管理员 | mTLS + CA、会话 Cookie、令牌签名 | 密钥/口令失守；bootstrap token 管理 |
| Tampering（篡改） | 改受保护文件、改策略、改审计 | 写入阻断、策略签名、审计链签名 | root；服务端数据库 |
| Repudiation（抵赖） | 否认发布或写入 | 令牌 + manifest + 签名审计 | 私钥泄露后可伪造；时间戳无第三方背书 |
| Information Disclosure（信息泄露） | 令牌、密钥、审计内容泄露 | TLS、0600、浏览器不接触令牌 | 服务端数据库明文；发布端主机被控 |
| Denial of Service（拒绝服务） | 杀 Agent、降级、控制面故障 | 心跳告警、degraded 标记、心跳下发撤销 | 主机被 root 控制后无法防 |
| Elevation of Privilege（提权） | Web 用户提权到 root、令牌越权 | 令牌路径/节点/TTL 绑定、进程白名单 | 提权本身不在产品范围；root 后失效 |
